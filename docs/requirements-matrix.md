# Consolidated BSSAPI requirements — implementation cross-check

| Requirement                           | Delivered implementation                                                                                                                                 | Configuration / validation boundary                                                                                                                                      |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| API operation forms                   | Registered GET/POST/PATCH/DELETE operations, path parameters, allowed filters, JSON bodies, raw JSON and business table views                            | Administration → API settings; only registered operations execute. Supplied specification informs initial mappings; this is not every endpoint in the 2019 PDF.          |
| Direct relative paths                 | Same-origin portal proxy accepts paths such as `/subscriptions/320589947/balances`                                                                       | Register the corresponding subscription ID and MSISDN first. Absolute URLs, traversal and unregistered paths fail closed.                                                |
| Test / Production                     | Independent base URLs, enablement, live/simulated mode, auth variable references, write controls, timeouts, polling, TLS and optional CA file            | Dummy `.invalid` URLs supplied as requested. Test simulated; Production disabled.                                                                                        |
| Configurable TLS bypass               | Per-environment `tlsVerify` boolean, default true; false disables verification for that environment's upstream BSS request only                          | Admin-only configuration; audited. Package/install TLS verification remains enabled.                                                                                     |
| Configurable port / working directory | `PORT` or `server/portal.config.json`; absolute launcher resolves project config and env files                                                           | `node /absolute/path/scripts/portal.mjs dev` works outside the checkout.                                                                                                 |
| MySQL                                 | Primary database, parameterized SQL, persistent accounts/sessions/settings/results/evidence                                                              | MySQL 8.4 validated; Compose supplied. Explicit SQLite compatibility mode retained.                                                                                      |
| Preserve existing data                | Additive SQLite → MySQL copy preserves user password hashes and existing documents; source SQLite is not removed                                         | Marker makes reruns idempotent; target records take precedence. Re-login required; old sessions are not copied.                                                          |
| Account lifecycle                     | Login/logout, self-registration pending approval, admin creation, approval/rejection/disable, password change, recovery request and one-time reset token | No email delivery. Admin supplies reset token directly to account owner; token expires and cannot be reused. No AD integration.                                          |
| Custom roles                          | Create, rename, edit, assign and delete custom roles; per-page and BSS read/write/delete permissions                                                     | Assigned/default roles cannot be deleted until reassigned. Reserved Admin cannot lose full access; last active Admin cannot be demoted/disabled.                         |
| Protected pages                       | Signed-out page redirect; filtered menus and server-side authorization                                                                                   | APIs recheck current user status, role, and page rights.                                                                                                                 |
| MSISDN registry                       | Friendly name, MSISDN, subscription ID, environment, owner, assigned users, enabled state, approval and remarks                                          | Same number is unique within an environment; sharing uses one registration with multiple users. Test registrations auto-approved.                                        |
| Sharing                               | Owner and Admin can edit assigned users; shared users can execute within their own role permissions                                                      | Central sharing toggle immediately gates access. Assignees cannot re-share or alter ownership.                                                                           |
| Production approval                   | Configurable requirement, pending/approved/rejected decisions                                                                                            | Changing an approved number or subscription target requires renewed approval. Disabled/pending/rejected records cannot execute.                                          |
| Subscriber enforcement                | Common gate for direct requests, forms, reports, Subscriber 360, assistant and legacy purchase scenarios                                                 | Unknown paths blocked; catalog resource reads are an explicit read-only exception. Request polling requires a known purchase receipt linked to an authorized subscriber. |
| Bundle CSV / text                     | Four-column format, multiple offers and DA unit assertions, per-record OK / NOT OK, missing and mismatched detail                                        | Configurable source operations, JSON paths, product association and unit aliases. No empty/unknown mapping is counted as a pass.                                         |
| Extend verification APIs              | Administrators add subscriber GET operations and verification mappings                                                                                   | Deployed JSON shapes and product/offer/DA association must be mapped; simulator fields are not claimed as live schemas.                                                  |
| Subscriber 360                        | MSISDN / registered subscription identifier search, left summary, detailed resource tabs                                                                 | Available configured APIs queried. Device mapping initially disabled because deployment details are unconfirmed. Empty/unavailable results remain explicit.              |
| Product explorer                      | Single or multiple subscribers; returns only records associated with selected product                                                                    | Product association JSON paths are administrator-configurable.                                                                                                           |
| Batch Report                          | Comma-separated MSISDNs, product/offer/DA inputs, saved per-record reports and evidence download                                                         | JSON evidence download plus existing purchase CSV exports.                                                                                                               |
| Business assistant                    | Individual/batch balance, package, usage, availability and purchase plans; shared BSS services                                                           | Rules mode works offline. Optional OpenAI-compatible provider configurable; strict schema, same environment, policy gates, review and confirmation still apply.          |
| Admin assistant                       | User, role, permission, sharing, approval, environment, operation and settings actions                                                                   | Common natural commands plus typed JSON action payloads cover GUI actions. Passwords entered separately. One-time plans expire and cannot replay.                        |
| Central configuration                 | MySQL documents for roles, environments, registry, policies, verification and model settings; server files/env for port and credentials                  | No credential values in saved GUI settings or uploaded archive.                                                                                                          |

Live telecom API compatibility and a real model provider require deployment credentials/schema validation. Dummy URLs are intentionally not contacted during the simulator checks. Full enterprise SSO, distributed workers, maker/checker campaigns, immutable audit, PDF/XLSX reports and HA remain outside this consolidated implementation.
